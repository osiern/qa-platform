# 10 одинаковых E2E на трёх стеках

Сначала выполни сценарий руками, затем напиши тест. API создаёт только предусловия; проверяемые действия остаются в UI. Ровно один E2E на файл. Шаги ниже собраны из прогона TS и совпадают в JS и Python.

## 01. Авторизация: вход, сохранение сессии после обновления и выход

- JS: `js-wdio/tests/01-login-session-logout.spec.js`
- TS: `ts-playwright/tests/01-login-session-logout.spec.ts`
- PY: `python-playwright/tests/test_01_login_session_logout.py`

Предусловия: Через API создаются уникальный пользователь и товары (1 шт.). Браузерный контекст новый. После сценария удаляются только его данные.

- `it` Ввести email.
- `it` Ввести пароль.
- `it` Нажать «Войти».
- `check` Email пользователя отображается в шапке.
- `it` Открыть профиль.
- `check` В профиле отображается email пользователя.
- `it` Обновить страницу.
- `check` После обновления пользователь остаётся авторизован.
- `it` Нажать «Выйти».
- `check` Снова показана форма входа.
- `check` Email исчез из шапки.

Объясни: Сессия и где она хранится (токен в localStorage, сессия в Redis); зачем проверять состояние после обновления страницы; почему выход подтверждают два факта — форма видна и email исчез; изоляция browser context между тестами.
